
# Internationalization

All user-facing text is localized with `vue-i18n`. Never hard-code display strings.

## Usage

- In components/composables: `const { t } = useI18n()` then `t('namespace.key')`.
- Outside the setup context (utils, interceptors): `import i18n from '@/i18n'` and use `i18n.global.t`.

```vue
<template>
  <Label>{{ t('admin_organization_form.field_options') }}</Label>
</template>
```

```typescript
toast.error(t('global.duplicate_value'))
```

## Locale files

Keys live in `src/locales/`: `de_DE.json`, `en_EN.json`, `fr_FR.json`.

- Add every new key to **all three** locale files — never just one.
- Keys are `snake_case`, grouped by feature namespace (`global`, `admin_organization_form`, `errors`, ...).
- Reuse generic keys from the `global` namespace for shared words (`global.add`, `global.cancel`, `global.duplicate_value`).
- Pass dynamic values as params: `t('app.toast_error_unused_variable', { unusedVariables })`.

## Error translations

Error toasts resolve keys under the `errors.<namespace>.<errorCode>` path (see `@/lib/error`). When introducing a new backend error code, add the matching `errors.*` keys in every locale.
